# 每周5小时变2小时：计划调整案例

## 用户问题

用户已完成文献读取，仍需完成问答、引用与测试。每周可用时间从5小时降至2小时，距离希望完成的时间还有4周。

| 剩余内容 | 估时 |
| --- | ---: |
| 问答、引用、基本测试等核心工作 | 540分钟 |
| 可后移的美化与批量支持 | 240分钟 |
| 新预算下4周容量 | 480分钟 |

即使后移全部可选工作，核心仍差60分钟；按夹具估时至少需要5周。容量用于说明取舍，用户结合真实执行情况核对。

## 产品方案

1. 输入新每周投入、执行反馈和参考周期。
2. 为未完成任务选择允许修改、保持原样或本周期暂不安排。后移只对可选工作开放，由用户确认它不是最终成功标准的必需能力。
3. 选择延长周期或后移可选工作，生成独立调整草稿。AI可修改选定任务的行动、范围、分钟与完成条件；用户也可手动编辑。
4. 对照原计划检查预算、安排和逐字段差异，填写调整依据并明确确认后应用。
5. 继续完成下一项实际任务，完成记录和XP延续。

延期改变安排周期；后移的任务继续保留在计划中。核心目标的成功标准保持一致，不能只把预计分钟按2/5缩短。

## 领域保障

任务ID、章节、顺序、难度、已完成内容、历史流水及其他目标保持稳定；只修改选中pending任务。保存失败或基线过期保留原正式计划；确认前差异可重查，放弃草稿后原计划继续生效。

## 回归依据

固定场景见tests/evals/replan-5h-to-2h.json，执行档案夹具见src/test/replan-fixture.ts。领域与交互测试覆盖540大于480时阻止确认、5周选择、可选任务后移、范围/估时/标准联动、过期差异、保存失败、完成记录和XP保全，以及确认后继续完成任务。

这个案例用于验证产品决策与业务约束。真实用户调整后的恢复执行指标按[评测规范](AI_EVALUATION.md)开展观察。
