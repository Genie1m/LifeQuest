## 1. 协作和 Git 约定

- 当前工作目录原有 `research-onboarding-agent/`，其 README 与产品摘要显示为另一项目。LifeQuest 使用独立 `lifequest/` 目录与 Git 仓库，不移动或修改原项目。
- Step 1 规划提交为 f327cfe；Step 2 已在同一历史上建立 main/dev，本地开发仅在 dev。
- 后续每个步骤开发 → 自检 → 提交 → 提供验收说明 → 停止，等待用户通过后再启动下一步。用户反馈的修正另行提交，避免改写历史。
- 每个独立且通过基础检查的模块都提交；一个步骤较大可分多个模块提交，不把未通过检查的代码当作已完成成果。
- 提交前检查 Git diff 与 status，仅按明确路径暂存本任务文件，禁止 git add . / git add -A。不改无关 Git 配置、不使用破坏性重置。任何 push、远程分支创建、PR 创建和远程合并均需用户明确批准；批准后仅发布指定已验收版本。若缺提交身份，报告阻碍并取得身份信息，不自行编造。

## 4. 最终 MVP 验收脚本

1. 使用独立浏览器上下文首次打开：创建角色，选择头像；刷新后无需重新创建。
2. 创建目标“完成产品作品集”，选择创造方向，填写具体交付标准、基础和每周 5 小时；再次建目标被引导回现有目标。
3. 生成 Mock 建议，修改一项完成标准、增删任务、上下移动阶段与任务；刷新仍能继续编辑。
4. 构造空阶段/非法分钟数，确认被阻止且字段定位清楚；修复后预览并确认，进入执行界面。
5. 完成一个标准任务，得到总 XP 40、创造经验 40；快速重复点击、重载均不会再结算。角色页可回到对应任务。
6. 在领域测试夹具中从 80 XP 完成 40 XP 任务，确认 Lv.2、进度 20/100；所有能力经验之和等于总 XP。
7. 发起修改并尝试改/删已完成任务与阶段，操作被阻止；草稿期间无法完成其他任务；放弃修改回到正式计划。
8. 申请调整，将每周投入从 5 小时改为 2 小时，查看原因和任务对照；先拒绝，确认正式计划/XP/投入均不变；再次生成并接受到草稿，手动微调，确认后才生效。
9. 模拟存储写入失败，确认任务仍未完成且没有新增 XP；恢复后重试只结算一次。损坏/未来版本数据不会被空状态覆盖；另一个标签页写入后旧页冻结并要求重载。
10. 完成其余任务，阶段与目标成就各解锁一次，历史目标只读，可以创建新目标；无需登录、真实 AI 或数据库。
11. 在手机宽度与桌面检查导航、编辑、确认、任务抽屉和成长反馈；键盘可完成核心操作，动画不阻挡下一次操作。

## 5. 主要风险与处理

| 风险 | 首版处理 | 何时复查 |
| --- | --- | --- |
| 退化为 Todo 游戏皮肤 | 强制完成标准、阶段成果与目标能力归属，经验可追溯到任务 | 第 5–6 步真实演示能否解释成长来源 |
| Mock 质量有限、误认为真实 AI | 明示 Mock；确定性模板；完整手动路径；不声称真正理解自由输入 | 第 5 步测试不同目标与每周投入 |
| 自选难度带来数值失真 | XP 定义为投入记录，无排行榜/兑换；不做反作弊 | 引入社交或真实权益前 |
| 完成不可撤销易误触 | 提交前确认，显示标准与奖励；文案明确完成后锁定 | 第 6 步验收用户反馈，必要时另议撤销设计 |
| 单目标、不可放弃限制长期使用 | 清楚标为 MVP 约束；验证一条闭环后再评估多目标与放弃流程 | 首轮真实使用反馈后 |
| 本地数据丢失与并发覆盖 | 诚实提示边界；整快照写入、版本校验、错误保留、冲突冻结 | 第 2/8 步；接入账号前 |
| 执行中编辑破坏历史和重复奖励 | 正式计划/草稿隔离；锁定完成内容；唯一流水；重新确认 | 第 6–7 步回归 |
| 后续迁移低估工作量 | 保留 UUID 和端口，但明确 Auth、RLS、事务、导入需单独开发验收 | 进入 Supabase 阶段前 |
