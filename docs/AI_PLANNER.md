# AI规划与质量评估

## AI在产品中解决什么问题

把用户的成长愿望转化为可以开始执行的路线，并在个人条件变化后提供调整建议。规划依据包括目标、最终成功标准、当前基础、周投入、学习偏好、资源限制和其他要求。

输出以章节组织，每章有里程碑，每项任务给出具体行动、完成条件、预计分钟和难度。规划理由、假设和提示与建议一起展示，方便用户理解与修改。

## 从建议到执行

**收集条件 → 生成候选 → 用户审核 → 导入编辑器 → 保存草稿 → 确认开启。**

产品把建议与正式计划分开处理。用户可以接受、拒绝、重新生成，也可以手动规划。接受建议进入编辑状态；正式确认使计划生效。修订已有目标时，沿用原执行记录，展示具体变化后再应用。

## 模型与凭据

统一RealityPlanner接口连接OpenAI、Qwen和OpenAI兼容中转，Adapter处理Responses/Chat及不同JSON输出能力。用户在模型设置中选择服务商、协议、模型ID与端点，使用自己的API Key测试连接。

凭据驻留会话内存，经本机LifeQuest服务端发送给配置的供应商；连接切换会取消旧请求，刷新后重新配置。连接测试、生成错误与请求耗时帮助定位权限、配额、网络或结构问题。

## 让任务更容易执行

规划指令将“学习、熟悉、掌握”进一步落实为行动对象、操作步骤和成果检查。例如把“学习数据处理”细化为读取一份样例CSV、处理缺失值、输出汇总并验证结果。

模型填写每项任务的预计分钟，产品按任务求和并结合周预算给出最低参考周数。审核时提示说明与逐项估时不一致、较长任务、位置偏早的检查点，或可能把失败记录误算成交付的验收条件。语义提示来自有限规则，由用户核对并决定是否修改。

生成先梳理最终成果及必要能力，再安排前置学习、独立工作单元和验收。任务数量随成果与可用时段确定。诊断交付检查报告，实践交付真实尝试与观察，功能实现交付实际工作结果；没有发现错误时保留通过证据，不要求制造问题。多组作品逐组补齐，明确的实践周期对应各周行动与记录。

审核区保留本次请求的成功标准、偏好和限制供对照，提示具体任务及修改方向。规则检查与内容评分分别记录；数量匹配、检查点位置或未出现提示，都不直接代表语义达标。预算重规划保留原任务引用与难度，在既有任务内说明行动和取舍。

任务编辑器支持在原行动后插入待填写的拆分任务。用户分别填写两项的行动、估时与完成标准，再核对检查点。预算调整保留任务标识，继续逐项核对范围、时间与验收标准。

## 60组输入，8项质量标准

五类场景各12组，覆盖编程学习、AI项目、面试准备、运动习惯和创作实践。每类包含不同基础，并结合预算、偏好、资源条件、信息缺失与提示注入设计输入。

| 维度 | 评价重点 | 方式 |
| --- | --- | --- |
| 结构合法性 | 字段、引用、任务归属与领域导入 | 程序检查 |
| 目标一致性 | 章节和任务是否支撑最终成果 | 人工1～5分 |
| 基础适配性 | 前置知识、难度与已有能力是否匹配 | 人工1～5分 |
| 时间合理性 | 工作量、周期假设与预算取舍 | 人工1～5分 |
| 任务可执行性 | 行动对象、步骤和交付是否明确 | 人工1～5分 |
| 完成标准可验证性 | 是否有可观察的成果与检查条件 | 人工1～5分 |
| 阶段逻辑合理性 | 顺序、依赖、反馈与实践衔接 | 人工1～5分 |
| 内容与事实可靠性 | 重复、无关内容、假设和事实依据 | 人工1～5分 |

评测流程由程序校验、AI辅助预审和人工复核组成。AI帮助定位问题和整理判断依据，人工按表中锚点逐项评分并确认结论；两类记录分别保存。合格条件为结构通过、七项均至少3分，其中目标一致性、可执行性、可验证性至少4分。首次生成、重新生成与人工修改分别记录。

评测工具逐条保存结果，记录模型、输入、Prompt与Schema版本、延迟、实际Token和主要问题，自动生成包含输入、完整计划、程序结果和人工评分栏的Excel。固定输入与记录机制让后续方案比较使用相同的评价口径。

批次记录质量检查版本及代码指纹，每次请求前复核；返回结果核对本机服务的规划版本，版本不一致时停止批次。旧输出可以另建规则审计，原计划与评分保持原样。[查看版本冻结与验证方法](AI_QUALITY_VALIDATION.md)。

问题分析聚焦新手前置、任务粒度、完成标准和成果承接，形成对应的规划指令与审核提示。内容评分用于判断方案质量，程序提示帮助定位具体任务。[阅读评测与改进案例](AI_EVALUATION_CASE_STUDY.md)

## 评测工具

输入见tests/evals/scenarios60.v2.json，评分规则与领域导入检查在tests/evals，采集入口为scripts/eval60.mjs，Excel导出与评分回导入口为scripts/eval-workbook.mjs。

启用本机真实模型服务，冻结后运行 `node scripts/eval60.mjs real tests/evals/relay.example.json <冻结文件路径>`，核对配置并在终端确认调用、隐藏输入Key。结束后批次目录生成evaluation.xlsx，人工填分后按样本ID回导。Excel使用Codex bundled表格运行库，配置与补跑见[操作指南](EVALUATION_GUIDE.md)。
