# 从计划生成到可执行路线：评测与改进案例

## 产品问题

用户需要的不是一段关于目标的建议，而是知道下一步做什么、投入多少时间，以及怎样判断完成。规划质量围绕这三个决策展开。

## 评测设计

固定60组不同合成输入，覆盖编程学习、AI项目、面试准备、运动习惯与摄影创作5类场景。每类包含不同基础，并组合周预算、单次时段、设备、资源、偏好和信息缺失等条件。

评价分为结构与内容两层：程序检查字段、引用和领域导入，内容依据目标一致性、基础适配、时间合理、行动明确、验收可判断、阶段衔接及事实可靠7项标准。

采用AI辅助人工评测流程设计：

1. **程序校验**：保存固定输入和输出，给出结构结果及安全错误分类。
2. **AI辅助预审**：逐项阅读计划，定位问题并整理与任务对应的判断依据。
3. **人工复核**：在Excel中按1至5分锚点填分，记录最终判断和依据；与预审结果分开保存。
4. **回归比较**：固定用例、版本和阈值，分别统计首次、补跑与用户修改后的表现。

工具支持完整计划、延迟、实际Token、版本与评分依据的采集和回导。工作簿与实验记录在本机管理。

## 从问题归因到方案调整

| 观察到的问题 | 产品判断 | 对应调整 |
| --- | --- | --- |
| 任务只有“学习、掌握”等概念 | 用户缺少明确起点 | 要求行动对象、操作步骤和可交付结果 |
| 多项复杂工作合成一个大任务 | 难以开始，也难以反馈进度 | 按单次可用时段和能力缺口组织独立工作单元 |
| 记录报错或写报告就算实现完成 | 过程产物替代了最终成果 | 区分诊断、实践、实现和最终验收的条件 |
| 没有遇到错误就无法完成修复任务 | 健康路径缺失 | 检查通过时保留证据，不强求制造缺陷 |
| 局部成果齐全，但最终作品缺项 | 局部完成不能代表目标达成 | 对照原始成功标准核查全部交付和最终展示 |
| 章节检查点早于必要工作 | 阶段反馈与真实进展不一致 | 将检查点与本章完整成果及依赖核对 |

规划指令据此围绕“成果与约束、前置与缺口、独立行动、完成标准、阶段验收”组织。审核区展示用户原始要求与具体任务提示，接受建议后仍可编辑，保存并确认后进入正式执行。

## 形成可复用的方法

产品规则负责边界，固定用例负责覆盖，AI辅助整理问题，人工复核负责最终评价。效果指标按同一输入、版本、生成次数与评分规则比较，避免把结构通过、补跑成功或修改后的结果混为首次质量。
