# LifeQuest 产品架构

## 设计目标

围绕“建议可以反复讨论，执行记录持续保留”组织系统。页面承接用户操作，领域命令处理目标与任务规则，Repository统一保存档案，Planner通过Adapter连接模型服务。

## 分层

| 层 | 职责 | 代码 |
| --- | --- | --- |
| 页面与组件 | 目标、计划、角色、执行与重规划交互 | src/app、src/components |
| 状态 | 初始化、保存队列、修订冲突、会话模型配置 | src/state |
| 领域 | 计划确认、任务结算、修订、预算调整与成长计算 | src/domain |
| 存储 | 加载、快照校验、版本迁移与写入 | src/services/repository.ts |
| AI服务 | 输入解析、请求适配、提案校验、错误分类 | src/services/planner |
| 评测 | 固定输入、自动检查、人工评分和Excel记录 | tests/evals、scripts |

前端使用Next.js App Router、React、TypeScript、Tailwind和shadcn/ui基础组件。交互通过Context与纯领域命令组织，快照保存在localStorage。

## 数据模型

| 实体 | 内容 |
| --- | --- |
| LocalProfile | 本地身份id与创建时间 |
| Character | profileId、昵称、兼容头像、职业与外观标识 |
| Goal | 角色归属、目标、成功标准、基础、方向、周投入、状态 |
| Stage / Task | 章节里程碑、检查点与任务行动、标准、分钟、难度、完成状态 |
| ExecutionPlan | 正式revision、完整内容、确认时间及调整信息 |
| PlanDraft | baseRevision、编辑内容、来源、更新时间及重规划设置 |
| CompletionEntry | 任务/目标/章节/角色归属、完成时内容、方向、XP与备注 |
| AppSnapshot | schemaVersion=2、revision、身份、角色、重点、目标和完成流水 |

ID使用UUID，日期使用ISO字符串，数组位置表示顺序。经验、等级、成就与进度由完成记录和任务状态派生。

## 一次用户操作如何保存

组件提交输入 → 领域命令生成候选快照 → Provider串行调用Repository → 校验预期revision并一次写入 → 发布新状态与反馈。

角色与身份、目标与草稿、任务状态与完成流水分别在同一次快照保存中更新。首次服务端与客户端渲染保持加载态，挂载后读取本地档案。外部标签页变更触发冲突提示，用户重新加载后继续。

## 草稿与正式计划

初次确认生成revision=1的ExecutionPlan，清除相应草稿。执行中修订以baseRevision指向原计划；用户保存、查看差异并确认后更新正式revision。

时间预算调整使用ReplanSettings记录weeklyHours、windowWeeks、requestedWeeks、feedback、selectedTaskIds、deferredTaskIds与extend/defer策略。确认时核对快照与目标基线，保存新预算及计划；完成流水与XP保留。

常规修订处理尚无进展或成果的章节，预算重规划处理选定pending任务。后者保留任务ID、进展备注、章节和顺序，逐字段核对已完成、未选中及推迟内容；范围、估时、验收与容量校验共同服务差异确认。

## AI规划链路

页面收集条件 → 本机POST /api/planner → RealityPlanner Adapter → PlanProposal → 结构与引用校验 → 用户审阅 → 转为编辑内容 → 保存并确认。

ModelSession单独管理Key与连接参数，页面切换保留会话，刷新后重新配置。服务端按OpenAI、Qwen及兼容中转的协议生成请求；本机开发通过显式开关启用，生产模式关闭该代理。凭据按请求转发，业务快照只保存计划与执行内容。

初始规划、常规修订和预算调整复用同一提案协议，分别由领域规则核对允许修改的范围。预算上下文使用临时引用映射选中任务，接受时再核对当前基线。

生成指令按初始、可编辑章节、选定任务三种范围组织，任务级调整保持一对一引用与难度。`plan-quality.ts`为纯函数，页面和评测共用带类别、章节/任务引用及建议的审核提示，并保留原需求对照。结构校验负责合法性，语义规则只提供审核证据，不自动评分、修改计划或发起付费修复。提案与本地快照格式保持不变。

## 执行与兼容

任务完成以taskId唯一结算，按难度增加20/40/60 XP；目标方向获得同份经验，每100XP升级。保存成功后返回本次奖励反馈，刷新后展示派生状态。

未完成的正式任务可选存储 progress，记录进行中、受阻、推迟及当前备注。它不生成完成流水，完成后通过同次快照保存清除当前进展字段并创建正式成果记录。旧档缺省进展字段时沿用待开始状态。章节进度、成就与完成回执共用章节完成判定。

旧档通过冻结的v1校验器验证、保留原文备份，再转换和校验为v2。旧头像和职业使用兼容映射，历史目标及完成记录保持身份连续。

## 质量保障

测试覆盖领域状态转换、重复结算、存储失败、旧档转换、AI结构与引用、修订历史保全及交互。评测按固定输入记录提案、模型与版本、延迟、Token、程序检查和人工评分，形成可复查的质量资料。
